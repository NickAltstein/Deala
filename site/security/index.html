DEALA / SECURITY

Defined boundaries.

Public demo posture and planned pilot controls are distinct.

Available in this package

Browser-local signature generation and verification. No external commercial actions. Downloadable pilot review brief; no inquiry data collected on this site. The verifier has a restrictive content security policy blocking network connections; the landing page uses external font and animation assets.

Receipt payload integrity is not proof of signer identity, factual correctness, production policy enforcement or completeness. Only the subject object (including its type) is signed in v2 demo receipts. Envelope metadata, including receipt ID and timestamp, is not authenticated. The included ephemeral public key is not a trusted production identity. Verification is local and checks the serialized subject and signature, not the truth of the commercial information.

Threat model

Untrusted messages, prompt injection, stale approvals, cross-tenant disclosure, unauthorized egress, replay and altered evidence are planned test categories.

Operating mandate

Design requirements: default deny; scope, expiry and revocation; governed reads; approval-bound drafts; no WhatsApp sending, offers, payments or outreach in the initial pilots.

Retention

Production retention, deletion, backup and access policies require validation before real dealer data is accepted. This standalone verifier uses page memory, not persistent storage. Do not paste confidential records into public demos.

Verification

Use the supplied signed sample, verify, then modify the payload and verify again. Production receipt compatibility and trusted-key distribution are not established.
